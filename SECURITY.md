# Security

## What the guard touches

- **The LAN access code.** The guard reads it from Bambu Studio's own configuration (`%APPDATA%\BambuStudio\BambuStudio.conf`) at each check. It sends it to one address only, the one it holds for the printer, over the MQTT port (8883, TLS): the address you named in `config.json`, or else the local address an announcement named for that printer ("The local network" below says what that rests on). It is not written to the log, the state file or any window.
- **The printer.** The guard subscribes to the printer's status reports and sends one status request ("report everything") each time a link to the printer is made: one for every check, and one for every link of the follower. While it follows a printer (for an entered amount, or for learning) it holds a link and reads every 3 seconds what the printer has reported on it. A link on which the printer has reported nothing for a minute is ended, and a new one is made a minute later, with its one status request. It sends no command that changes the printer: no print, pause, stop, temperature or motion command.
- **The printer's certificate is not verified.** The printer's certificate is not one a public authority has signed, and the guard accepts whatever certificate the address it connects to shows, without checking it. The link is encrypted, but the guard cannot tell the printer from a device that stands in its place: such a device receives the access code, and what it reports is what the card shows. Use the guard only on a network you trust.
- **The local network.** To find a printer's IP address the guard listens for the printer's own announcements (multicast, UDP ports 2021 and 1990); it does not scan. **Announcements are not authenticated.** Any device on your network can send one with your printer's serial number, which the printer itself announces, and so answer in the printer's place: the guard then connects to it and sends it the access code. What the guard does check: it takes an announcement only when it is marked as a Bambu printer's (`NT: urn:bambulab-com:device:3dprinter`), is for a printer it is looking for, and names a local IPv4 address. A host name or an address of the internet is dropped, so an announcement cannot send the access code off your network; a device on your network that names its own address is still taken for the printer. Naming the printer's address in `config.json` avoids discovery: the guard then never listens for that printer, and connects to that address only. `{"printers": {"<serial>": {"ip": "192.168.1.50"}}}`. A printer with a public address is found only that way.
- **The internet.** The guard makes no internet connection. The one exception is `build.py`, which downloads Python from python.org to make the packaged zip, and pip, which fetches the wheels `requirements-bundle.txt` names. Both are refused unless their SHA-256 is the one kept in the repository.
- **Files.** The guard reads the G-code Bambu Studio writes under `%TEMP%\bamboo_model`. Its log and state are in `%LOCALAPPDATA%\BambuFilamentGuard`, with `learned.json`, the history learning keeps: per printer serial and tray, the spools' RFID tag ids, their readings during past prints, the names of those print jobs, the guard's forecasts for those prints, the lowest reading each spool was seen still feeding at, the weights you entered for spools the printer measures, and the printer's error and HMS codes when a spool ran dry. It stays on this computer; `learned --forget` empties it, and keeps what it held beside it as `learned.json.forgotten` (one copy): delete that file to be rid of it. `state.json` and `learned.json` each have the version before their last change beside them (`state.json.bak`, `learned.json.bak`): the guard goes back to it when the file itself is damaged or gone, as after a power cut. Whatever you have the guard forget takes that copy with it, so that it cannot come back from there: `learned --forget` for everything or for one tray, a weigh-in taken back with `learned --forget-weigh`, and an amount removed with "Forget this amount". The guard and a command run beside it write these files one at a time (a Windows named mutex), so neither undoes the other's change. Its settings are in `config.json` in the same folder (up to 1.4.0 that file was beside the script, where it is left when its settings are brought over). Starting automatically adds a shortcut to your Startup folder. The log and state can hold printer serial numbers and IP addresses. The log also holds the titles of your projects, the names of your print jobs, and file paths under your Windows user folder, with your user name in them: take out what you do not want public before you paste log lines into an issue.

## Report a vulnerability

Use GitHub's private vulnerability reporting: open this repository's **Security** tab and choose **Report a vulnerability**. Please do not open a public issue for a vulnerability.

Say what you found, how to reproduce it, and which version of the guard it affects. Never include a real access code or serial number in a report.

Only the latest release is supported.
